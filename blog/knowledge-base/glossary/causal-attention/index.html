Causal attention

A rule that lets each token use itself and earlier tokens, and not later ones.

Causal attention lets each token use itself and earlier tokens, and not later ones. Decoder-only language models use this rule so that a next-token prediction is a function of the past.

Each token contributes two vectors for other tokens to read, a key and a value, and carries a query that it uses to look those up. Under a causal rule, the keys and values at a prefix position are computed only from the prefix up to that position. A token that sits later does not enter that calculation.

Worked example

Label the slots \(A\), \(B\), and \(x\), with \(x\) last. The allowed reads are:

Slot May read Its keys and values depend on
\(A\) \(A\) \(A\) only
\(B\) \(A, B\) \(A\) and \(B\)
\(x\) \(A, B, x\) \(A\), \(B\), and \(x\)

Replacing the vector in the last slot changes the query, key, and value at \(x\). It does not change the keys and values at \(A\) or \(B\). That is why a fixed prefix can be processed once while a soft token in the last slot varies.

This is not the same object as a padding mask. An attention mask can also mark padding, or encode this causal rule as a grid of allowed pairs. Which job a mask is doing is a property of the implementation.

See also: attention mask, transformer, residual stream.
